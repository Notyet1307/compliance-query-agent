# 产品范围与首版业务闭环

状态：**初始设计草案**。用户明确的目标保留；其余推荐待接管核验与业务确认。

## 目标用户、问题和结果

直接使用者是安全售前/咨询、安全运营与合规管理人员，未来通过 Accord 发起查询。当前痛点是假设：资料分散、版本不明、答案无法定位原文、同一问题因模型或资料变化而难以复核。需要用户在首次真实样例验收中确认，而不是宣称已访谈验证。

业务结果：给一个问题、主题、查询截止日期、地域和行业范围，取得有明确依据的片段/说明、来源版本与定位、未解决项和人工复核提示。没有依据时，看到真实的“不足/待复核”，而不是自信补完。

## 已确认的五个领域

| 领域 | 建议支持的首版问法 | 必须保持的边界 |
|---|---|---|
| 信息安全等级保护 | 某控制点要求如何描述，出处和版本是什么 | 不仅凭“三级”自动判定所有适用条款 |
| 关键信息基础设施保护 | 某保护职责或程序的资料依据是什么 | 不自行认定一个系统是否为关基 |
| 安全政策 | 某政策内容、版本、发布日期和适用范围 | 正式文件、草案、解读、内部制度分开 |
| 行业知识 | 某行业术语/工作要求有哪些可引用资料 | 经验知识与监管要求分层 |
| 商用密码应用安全性评估 | 某评估主题的资料依据和术语解释 | 不代替具备资格的实际评估活动 |

五个领域由一个共用查询流程承载；首版每次请求显式指定一个 topic。跨领域对比、自动识别主题和多轮澄清是后续候选，不偷偷算作当前能力。

## 最小完整业务流程

用户输入 → 范围/日期验证 → 经批准的资料源检索 → 片段与元数据校验 → 时间/版本过滤 → 原文提取或 LLM 参考草稿 → 引用集合校验 → 本地执行回执 → 结构化结果。

接入后由 Accord 承担接收、上下文冻结、选用角色、人工决策与最终发布；由 agent-compose 承担运行环境；OctoBus 提供受限数据方法。本智能体内部只做一次查询，不另建计划器、调度器或长期任务。

## 代表性输入输出

正常软件样例：`examples/mlps.json` 问“演示材料中的资产清单需要记录什么？”，在虚构片段中得到原文与可验证的 SHA256，`status=REFERENCE_ONLY`、`dataMode=synthetic_demo`。这证明软件链路，不证明等保知识正确性。

代表性真实业务问法：`examples/insufficient.json` 问“三级系统审计日志应保留多久？”。当前没有对应真实资料，因此输出 `INSUFFICIENT_EVIDENCE`，claims/citations 均为空。不在样本中塞进未经核验的真实条文或数字。

时效异常：匹配片段的核验日期早于请求日期 → `NEEDS_REVIEW`。版本冲突：同一文档和定位有重叠有效但内容/版本不同的片段 → `NEEDS_REVIEW`。没有完整原文或权限证明时，不让模型绕开限制。

## 首个真实里程碑的推荐

先由用户提供或批准一小批等保资料，建立 20–30 个带人工答案与引用的评测案例；再补齐其余四个领域的代表性真实样例。这个数量是工程建议，未获批准，不能作为既有承诺。知识范围仍保留五域，但不以“大而空的完整知识库”阻塞第一条价值链路。

## 默认部署假设

个人 Mac 开发，之后运行于受控 Linux/容器环境；Go CLI/API；真实模型与知识服务可走私有网络或经批准的外部服务。当前只是推荐，未验证用户机器、服务器架构、网络或镜像权限。

业务查询不要求独立新页面；未来 UI 由 Accord 提供，所以启动包有实际可运行 CLI/API，不另造聊天应用。

## 本版不做

自动合规判定/发证，等保定级/关基认定，自动整改、真实系统写入，五 Agent 相互辩论，复杂自治工具规划，全网自动抓取，未经授权标准全文再分发，向量数据库/队列/Kubernetes 控制层，多租户与公网服务，替换 Accord R003，接管旧 Planner/Controller。
