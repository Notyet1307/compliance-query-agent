## Problem Statement

S1 已验证同一测试文档上的本地模型参考草稿；X1 已验证 guest 经原生能力通道调用 OctoBus 的合成 Search，但只做原文提取。两段证据不能拼成已经通过的受管模型链路。X1 的临时回执在 guest 容器替换后丢失，新 sandbox 会再次检索，因而不能安全地把“环境重建后再运行一次”当成完成结果重放。

操作者需要在受管环境中得到有引用和 Token 记录的同一类参考草稿，并在限定的同机重建后取得已保存结果，而不是重复检索、再次生成或掩盖未知执行结果。

## Solution

保留一个固定 Go 查询流程：guest 通过原生能力通道调用 OctoBus 的固定只读 Search，筛选同一合成测试文档，再通过 agent-compose 既有模型代理调用百智云 Grok。模型不经 OctoBus，不启动第二层编码代理或工具循环。

上游模型密钥留在 daemon；OctoBus 管理凭据留给预置操作者，daemon 优先仅持查询凭据。将既有文件回执存于同机、同项目／角色的专用持久目录；guest 替换或新建 sandbox 后，在同一构建和稳定业务配置下原样重放完成结果，不新增 Search 或模型调用。未知请求阻断，不自动恢复。

## User Stories

1. 作为查询者，我希望在真实受管 guest 中使用已接受的同一测试文档，以便比较受管链路与本地链路，而不是另换资料规避问题。
2. 作为查询者，我希望收到 `DRAFT_READY`、可核对的引用和人工复核提示，以便分清模型参考草稿与原文提取。
3. 作为查询者，我希望测试资料始终标为 synthetic，以免受管环境被误当成真实法规审核或生产认证。
4. 作为查询者，我希望没有依据或来源待复核时不调用模型，以免用模型记忆补造义务。
5. 作为操作者，我希望 guest 不持百智云真实密钥，以便使用平台已有的凭据边界而不自建转发服务。
6. 作为操作者，我希望知道平台代理凭据并非单模型白名单或费用上限，以便在明确的隔离测试范围内接受风险。
7. 作为操作者，我希望查询链路不用 OctoBus 管理凭据，以免为资料查询扩大管理权限。
8. 作为操作者，我希望权限或协议不兼容时明确停止，以免系统自动升权、直连或切换模型。
9. 作为查询者，我希望重复提交已完成的同一业务请求取得原结果和原用量，以免重复调用或重复累计 Token。
10. 作为操作者，我希望同机替换 guest、包括新建 sandbox 后仍可重放，以免短暂运行环境决定业务请求是否被再次执行。
11. 作为查询者，我希望同 ID 的问题、业务关联或稳定配置发生变化时被拒绝，以免旧结果绑定到另一请求。
12. 作为操作者，我希望挂载、权限、回执损坏或预留写入失败时停止联网，以免丢失去重保护后继续执行。
13. 作为操作者，我希望超时、取消和未完成回执保留未知状态，以免本地退出被误称远端停止或未计费。
14. 作为验收者，我希望每次运行都能关联固定输入、平台运行引用、结果、回执和调用计数，以便验证完整业务链路而非只看启动成功。
15. 作为验收者，我希望 Token 缺失、部分、未知与未调用明确区分，以免把记录当成账单或费用控制。
16. 作为操作者，我希望恢复保证明确排除升级、跨机和丢库，以免把一个持久目录误当成分布式恢复系统。
17. 作为资料审核者，我希望来源文本不能选择端点、模型、权限或命令，以免查询数据变成执行指令。
18. 作为验收者，我希望软件模拟、真实集成、人工接受和未执行项分别留证，以免历史 S1／X1 结果被挪用为 S2 通过。

## Implementation Decisions

### 受管测试模式与复用边界

- 复用现有查询 CLI、请求／结果协议、Engine、来源筛选、生成客户端和 Store；不新增业务测试 API、数据库、队列、控制器或通用 provider 注册框架。
- 为此次受管合成资料与 LLM 组合建立明确的测试配置边界，不能仅删除 X1 的 extractive 限制，不能使正式真实资料模式接受 synthetic。默认网络仍关闭；旧 X1 配置不因本规格自动转成模型调用。
- 复用固定原生 Search 接缝和既有领域知识协议；本轮只将同一测试文档供给受控知识服务，不建设生产知识库。协议是本项目的领域服务契约，不是 OctoBus 内置知识库。固定客户端子进程仅作为低频测试实现复用，不批准其为所有后续生产场景的永久接口。
- 一次 command 执行一次查询。输入走固定、受控的 JSON 文件，不将问题、正文、关联值拼进 shell，不假定平台 command REPL 可以透传 stdin。guest 不挂载 HOME、宿主根、Docker socket 或包含无关凭据的完整仓库。

### 模型、数据与权限

- 固定百智云 `grok-4.6`、Chat Completions、非流式 JSON Object，沿用 S1 的最小请求字段与 `max_tokens:2048`。这不是完整计费输出上限，也不声称关闭隐藏推理。
- 复用 agent-compose 模型代理。guest 仅获得 sandbox 范围的平台代理凭据；真实上游密钥由 daemon 注入。CQA 只调用批准的 Chat Completions 路由，不读取 OMP 个人配置或凭据库，不新建转发服务，不自动回退 guest 直连。
- 运行连接信息由受信平台注入，并校验批准的 daemon、sandbox 路由和协议；不得为兼容代理而放宽为任意 HTTP／URL。若测试内部通道使用明文，须在运行包中明确网络边界与风险，不沿用 X1 授权或推广为生产传输方案。
- 固定平台版本的代理凭据绑定 sandbox／provider／协议，**不强制限制为 Grok 单模型，也不提供费用上限**。用户接受此隔离测试取舍；CQA 固定模型并不等于平台阻止恶意 guest 使用 provider 的其他模型。
- 模型只收到固定提示词、测试问题、查询日期及本次证据的 ID／标题／定位／原文。不给模型业务关联、完整回执、来源 URL、客户材料、管理权限或工具；引用元数据由检索结果产生。
- OctoBus 的预置管理凭据仅由操作者使用；daemon 优先只持固定 capset 的查询凭据，guest 只持平台能力凭据。必须同时验证认证、固定 Search 与平台目录流程的实际兼容性。目录失败仅有告警不是通过证据；不兼容时停止回到用户决策，不复用 X1 管理级测试 token，不自动升权或改走 Direct。
- 继承无重定向、无环境代理、无模型回退和无自动重试；执行包还须观察平台代理到上游的实际转发，不把 CQA 单次发送等同于未经验证的全链路零重试。

### 业务请求身份与完成结果重放

- 保留 `cqa.query/v1` 与 `cqa.result/v1`。同一业务请求要求同 `requestId`、全部业务输入及稳定配置；可选 Case／Invocation／contextDigest 仍整体校验和绑定，不授予权限。
- 平台 run／sandbox 引用作为执行证据另行记录，不替代 requestId，不因新建运行就修改业务 Invocation。同 ID 的业务输入或稳定配置变化仍为 `IDEMPOTENCY_CONFLICT`。
- 必须分离稳定业务／模型／权限配置与临时连接地址、轮换的凭据值。保留资料配置、capset／instance、模型、网络批准、等待上限、稳定路径和凭据引用等有效配置绑定；不能为了新 sandbox 重放而取消配置摘要。
- 现有摘要包含整个配置；平台代理 URL 含 sandbox ID。因此不能把解析后的临时 URL 直接纳入稳定配置摘要。仅新运行地址／同权限凭据轮换不应产生业务冲突；真实配置改变仍必须冲突。跨构建迁移不在保证内，不能把 Agent 版本字符串当成二进制 SHA。
- 专用宿主回执目录只供同一信任范围的项目／角色使用，预置为私有权限并绑定稳定 guest 路径。复用 Store 的预留、完成、blocked 状态和原子保存；不复制旧回执到新空目录伪造持久重放。
- 恢复范围限同一宿主机、同一项目／角色、同一构建与稳定配置，覆盖实际 guest 容器替换及新 sandbox。新旧执行共享的是同一持久目录，不要求平台恢复已经失去 runtime 的旧 sandbox ID。
- 新请求必须先持久预留再发 Search／模型请求。已完成回执直接返回原结果、生成时间、摘要、引用与用量，不重查知识、不重新生成、不改写完成回执；重放不要求重新探活 Search／模型，但允许启动时要求当前运行配置和凭据存在。
- 受管启动必须确认预期持久挂载与权限，不能让 Store 自动建目录把挂载丢失伪装成首次运行。回执损坏、权限不安全、存储或预留失败均阻断；不绕过存储联网。该检查不提供磁盘丢失、管理员删库或单个回执被删除后的恢复／检测保证。
- `reserved`／`blocked` 同请求保持 `PREVIOUS_EXECUTION_UNRESOLVED`。超时或取消后不能证实的远端状态保留 unknown；不自动改 ID、删回执、重新检索或再次生成。响应后写盘失败不声称完成、无费用或安全重试。

### 结果、用量与运行证据

- 正常目标为 `DRAFT_READY`；原文提取不算通过。始终保留 `synthetic_demo`、`humanReviewRequired:true`、`entailmentVerified:false`。没有可用证据返回 `INSUFFICIENT_EVIDENCE`；来源待核验或版本冲突返回 `NEEDS_REVIEW`，两者均不调用生成模型。
- 继续拒绝伪造引用、工具调用、截断和不合格结构；仅有引用 ID 校验不证明语义正确。人工核对主体、条件、起算点、数值与引用文义，单独记录未展开内容及接受决定，不要求模型逐字复现 S1 草稿。
- Token 沿用 S1 的 `not_called`／`reported`／`partial`／`unknown`；保留 provider 原始计数，缺失不补零，不重算 total，不重复加缓存／推理或重放。有效草稿不因缺失 usage 被拒绝；失败但已有可解析用量仍留存，未知不当作未计费。
- 保存必要的命令、退出状态、输入／配置／构建摘要、run／sandbox 引用、回执摘要及调用增量。新运行可以有新的执行记录，但不得回写已保存业务结果。秘密、隐藏推理、完整 provider 原始错误不进入公开证据；平台日志和回执本身也不自动成为 Accepted Evidence 或防篡改审计。

## Testing Decisions

### 主验收面与测试先例

主验收面为**真实 query CLI → 结构化输出／错误、持久回执、服务调用增量**，在实际 agent-compose command 中复用同一入口。此验收面与下列 AC 已获用户审阅认可；不另建测试 API，不用平台 run 创建成功、healthz 或静态 YAML 通过代替业务完成。

软件异常先复用现有 Engine／Store、原生知识响应与本地 HTTP 协议测试；参照 S1 CLI 的真实子进程、输出／回执及调用计数检查，以及已有原生 Search 重放、来源校验、未知不重试测试。只为真实不确定边界保留回归，例如临时代理地址变化可重放而真实配置改变会冲突；不固定函数调用次序、源码文本或模型回答措辞，不为每条 AC 新建一套 mock。

### 三项真实可行性关口

| 关口 | 必须观察的事实 | 当前状态与停止条件 |
|---|---|---|
| S2-G1 模型代理兼容 | command 子进程获得适配 Chat Completions 的凭据；固定 Grok 请求经 daemon 转发，返回可校验的模型响应与如实用量；guest 不持上游密钥 | NOT_RUN；X1 Codex 槽位的 Responses 凭据不能直接当作兼容证明。拒绝、路由／模型不符或无法确认边界即停止，不下放密钥或直连 |
| S2-G2 最小权限 OctoBus | 仅查询凭据可完成真实认证和固定 Search；记录平台目录流程如何处理权限，guest 不可调用未授予能力或管理路径 | NOT_RUN；须排除关闭认证、残留管理凭据或扩大 capset 导致的假通过。不兼容则 BLOCKED，回到用户决策 |
| S2-G3 持久回执与身份 | 核对真实 host／daemon／guest 映射，guest 替换及新 sandbox 均读取同一完成回执；临时地址变化不冲突，新增 Search／模型调用均为零 | NOT_RUN；挂载、权限、摘要冲突或回执损坏即停止，不复制／删除记录补救，不把旧 sandbox 无法重建当成已恢复 |

可先用离线协议模拟和不调用模型的挂载检查准备关口，但不能据此把 G1–G3 记 PASS。G1 的真实转发证明应复用正常业务样例，不默认增加探活模型请求。正式执行顺序和每次新调用清单进入单独授权的运行包。

| S2-A13 | 源文本、日志与网络边界 | 受控恶意问题／正文不能改变命令、模型、端点或能力；检查 guest 挂载／网络和拒绝的越权路径，扫描本轮产物中的精确测试秘密；不得把一次扫描或请求固定声明为通用 DLP、系统隔离或单模型权限保证 |

软件验证须使用 `.go-version` 指定的目标工具链和 `make verify`，同时保留发生变化的 CLI 行为检查。离线 PASS 不代替实际 guest／OctoBus／模型验证；资料异常、错误输出与计数边界优先用受控模拟，未经逐项授权不向真实模型发送对抗变体。

调用增量须分别观察原生 Search 业务调用、平台代理接收与实际上游转发，不混淆平台目录请求、run 创建次数或回执读取次数。无法可靠观察“零新增”时，相应断言不能记 PASS；远端结果／费用未知保留 unknown。

## Out of Scope

- 真实法规现行性／来源许可终审、实际企业合规判断、关基认定、专业测评结论及五域真实知识覆盖；当前单文档测试不满足原真实资料 AC。
- RAG、上传／解析／审核／入库、向量库、扩充资料集、聊天 UI、多轮自主研究、工具循环、通用 Agent／任务控制器。
- Accord 调用／SQLite 写入、Accepted Evidence、审批发布或 trusted qualification；跨仓库修改。
- 自建模型代理、guest 持真实模型密钥、自动 Direct 回退、多模型选择、单模型平台强制权限、费用／次数闸门或完整账单保证。
- 查询链路的 OctoBus 管理权限、未批准网络访问、公开部署、生产隔离认证、多租户隔离。
- 跨机器／跨项目／跨角色恢复、程序升级／配置迁移、磁盘丢失／人为删除回执后的恢复或检测、自动恢复 blocked／unknown、自动删证据、密码学防篡改、跨系统 exactly-once。
- 本文之外的安装、镜像下载／构建运行、daemon／guest 操作、凭据访问、真实调用、任务发布和 Git 发布授权。

### 执行与验收入口

1. 用户已认可本文的主验收面、G1–G3 与 A01–A15；`/to-tickets` 的两张本地候选及其依赖也已获认可，不自动发布或授予实施权。

3. 真实运行前另行固定请求清单、期望、代码／镜像／配置／资料摘要、模型与查询凭据注入方式、网络／日志／数据处理风险、实际新调用边界、资源创建／重建／停止范围。S1／X1 的旧授权不续期，当前账号条款／处理地域／留存风险须核实或由用户明确接受。

5. 任一失败或未知立即停止该尝试，保留回执和运行引用；新尝试须另行决策，不能改 ID／配置或删记录“变绿”。结束时按已授权且确认归属的资源清单停止本次资源，不自动删除数据或证据。
