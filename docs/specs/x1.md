## 2. 最小路径与版本决定

```text
本机操作员
  → agent-compose RunService（固定 command + 固定合成输入文件）
  → Docker guest：compliance-agent
  → agent-compose 原生 OctoBus 网关（sandbox 授权）

  → 本服务证据筛选 + extractive 草稿
```

- 只用 Docker driver。agent-compose 优先 `v2609.2.0` / `043b763f05304c3a55f1bd3f4eb8504a591aa4ba`；daemon 和 standard guest 的 ARM64 digest 已在核验附件固定。CQA guest 从该固定 base 构建，执行前记录最终派生镜像 digest，不能把 base digest 当派生镜像 digest。

安全条件：

1. Docker socket 仅给受信 daemon，不给 guest；开启 daemon 控制面的认证，控制面凭据与 OctoBus upstream token、sandbox 调用凭据各自独立。
2. OctoBus admin 与 data 共端口，capset token 不保护 admin；guest 不应可直达 OctoBus admin。环境候选应分开 guest 网络和 OctoBus backend 网络，只让 daemon 同时接入。固定版会排序选择 daemon 所在网络，必须用实际 inspect 与受控网络探针证明 guest 网络选择；错误连接或 fallback default 时停止，不继续假定隔离成立。
3. host 管理端口仅 loopback，OctoBus backend 优先不映射 host 端口；由批准的操作员通道预置。guest 的普通网络权限不因 capset 声明而天然收紧；本试验只证明所测边界，不声称任意外联已被阻断。
4. 只挂载 X1 专用输入/状态目录，不挂整个仓库、HOME 或客户文件。daemon、Docker Engine 与 guest 三种路径分别记录；先证实映射，再发业务请求。
5. 测试 token 通过批准的环境引用注入，不放命令行正文、输入 JSON、提交文件、完整 inspect/env 输出或公开证据。只报告秘密反射检查的类别/位置/是否命中，不打印秘密本身。
6. 提供专用私有数据根，验证 guest 输入只读、回执目录 0700/文件 0600，以及平台日志在父目录约束下的实际访问权限。上游日志默认创建 mode 0644，不能用 CQA 回执权限替代它的检查。

### ADR-X1-01：隔离合成试验的 daemon 凭据

状态：2026-09-11 用户在本轮交互中选择“仅合成试验接受”，此试验限定决定已接受；不是生产 ADR 批准。

决定：在独立、无客户数据的本机 OctoBus 合成实例，同时开启 admin/capset 认证；允许受信 agent-compose daemon 持有两边有效的管理级测试 token，并执行原生目录注入所需的 admin GET。guest 仍只有 sandbox-scoped Search 权限，不获得上游 token 或 admin 能力。

## 5. 输入输出、身份和回执判定

- guest 使用常量 command 读取固定路径的 JSON。问题、来源正文及关联值都在文件中，不插入 shell。一次运行一个请求，不使用 REPL/PTY 来假定 stdin 透传。
- 优先 detached `run --command --json` 取得明确 `id`，再按该 ID 查询完成状态和输出，避免客户端等待被取消后丢失运行引用。detached 返回成功只表示创建运行，不表示查询成功。
- 证据分别记录 CQA `requestId/caseId/invocationId/contextDigest/inputDigest/configDigest/corpusDigest` 与平台 `project_id/agent_name/id/sandbox_id`。关联绑定不等于授权。每次新的 CLI run 可生成新的平台请求身份，同 CQA requestId 的回放仍应由已有 Store 决定。
- 平台 `result_json` 是 command/success/exitCode 元数据，不是 CQA 结果；`output` 可能包含 stdout/stderr。只接受完整、唯一且匹配现有 schema 的业务 JSON，不从前缀/混合日志中猜测截取。平台 success、命令 exit code、无 cleanup_error、业务身份和数据断言全部一致，才判正常行通过。
- 业务预期沿用合成 mlps 例：`REFERENCE_ONLY`，`humanReviewRequired=true`、`entailmentVerified=false`、合成数据与 extractive 模式标识，并逐项核对来源引用和输入绑定，不把这些标识当作实际合规结论。
- 现有 Store 的 completed 同摘要请求可回放；相同 requestId 改输入/配置为 `IDEMPOTENCY_CONFLICT`，reserved/blocked 为 `PREVIOUS_EXECUTION_UNRESOLVED`。试验不新增自动重试。
- 当前 guest-demo 回执在 `/tmp/cqa/receipts`，不承诺删除重建或跨 sandbox 存活。X1 必须观察该边界；若需要跨 sandbox 回放，专用持久目录及稳定 guest 路径是另一项明确配置决定，不靠复制旧回执或临时改摘要伪造通过。
