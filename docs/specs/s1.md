## Problem Statement

安全售前／咨询人员需要针对等保定级、备案问题获得可核对原文的参考草稿。当前合成样例不能证明真实资料、真实模型与人工参考答案形成闭环；地方窗口口径、旧版本及模型记忆容易被误当全国现行义务。

## Solution

以少量经人工确认的官方公开资料构成固定本地快照，回答全国通用依据层面的问题，使用固定 provider／模型生成有引用的中文参考草稿；新 provider 的实际处理地域尚未核验。依据不足或时效、版本有疑问时明确拒绝形成实质结论。资料取得、参考答案核验与模型生成分别留证，不把引用 ID 校验当语义证明。

地方入口、地方补充材料及窗口口径不进入首版全国答案；实际企业等级认定、是否合规通过和专业测评结论不由本服务作出。保持另外四个领域的范围声明，不以等保样例宣称其他四域已具备真实知识覆盖。

## User Stories

1. 作为安全售前／咨询人员，我希望按明确查询日期提出全国等保问题，以便知道回答采用的时间边界。
2. 作为查询者，我希望区分不同备案情形的条件、起算点和材料要求，以免把不同主体或阶段混为一谈。
3. 作为查询者，我希望逐项核对原文、定位、文档版本和来源，以便自行复核参考草稿。
4. 作为查询者，我希望没有依据时明确得到依据不足，而不是模型凭记忆补写条文。
5. 作为查询者，我希望时效未经核验或版本冲突时得到待复核结果，而不是看起来确定的现行结论。
6. 作为查询者，我希望地方办事指南不会被泛化成全国统一要求。
7. 作为资料审核者，我希望来源许可、效力核验与参考答案分别记录，以免一次网页抓取被当作全部审核通过。
8. 作为验收者，我希望对条件、否定、主体、数值和引用含义进行人工核验，不由模型自行打分通过。
9. 作为操作者，我希望只发送批准的公开样例，明确服务地域、留存风险、模型与可观察 Token 消耗。
10. 作为操作者，我希望失败、超时和结果未知不会触发自动重试，用量未知不会被记成零。
11. 作为验收者，我希望真实调用与本地模拟证据分开，能复核具体代码、配置、资料、输入和输出快照。

## Implementation Decisions

### 输入、资料与回答

- 复用既有查询协议、CLI、业务引擎、资料资格过滤、生成客户端与回执；不新增聊天平台、上传 API、工具选择或通用任务控制器。
- 首版请求使用 `topic=mlps`、`jurisdiction=CN`，不针对特定行业的全国问题使用 `industry=all`，查询日期显式固定；关联字段仍只是绑定，不授予权限。
- 本地资料必须来自逐项审核的真实公开来源，正常样例不得使用 synthetic 或把演示资料改名。每个来源固定原文、定位、版本、公开时间、有效区间、核验记录、文本与快照摘要；效力、适用条件与使用许可保留可复核记录。仅补充样例确实需要的元数据，不一次性实现治理建议的全部字段。
- 官网更新时间、代理抓取时间、搜索摘要和当前仍能访问，都不是现行效力的充分证明。来源不满足资格时保留 `NEEDS_REVIEW`，不为了取得正常样例而伪填审核日期或更换 status。
- 复用当前关键词检索，只有冻结真实样例证明召回不足时才作有针对性的修改；不得针对某条测试问题硬编码答案。
- 每条 claim 对应本次证据集合内的 ID；引用的 URL、原文、版本与摘要由程序产生，不接受模型覆盖。始终保留 `humanReviewRequired:true`、`entailmentVerified:false`。
- 继续使用 `DRAFT_READY`、`INSUFFICIENT_EVIDENCE`、`NEEDS_REVIEW`；`REFERENCE_ONLY` 不算真实 LLM 正常样例通过。

### 模型与数据边界（用户已确认）

- 本机 OMP 现有选择器为 `baizhi-chat/grok-4.6`，Chat Completions 基址 `https://ai-api-gateway.app.baizhi.cloud/api/openai`。复用现有 Go 客户端调用固定 `/chat/completions` 路径；不把 OMP 编码代理嵌入业务查询，不自动读取或执行 OMP 凭据配置。配置声明不证明网关模型可用性或境内处理。
- 外发范围仅固定提示词、经确认的非敏感样例问题、查询日期、证据 ID／标题／定位／公开原文片段。不发送客户资料、真实系统详情、内部制度、完整业务回执或无关关联数据。
- 百炼北京的公开样例非零留存批准、价格和地域结论不能转移给百智云代理。新 provider 的账号条款、实际处理地域和留存风险须在真实运行前核实并取得必要确认；不扩展到客户数据，不主动开启额外推理日志、训练、数据回流或联网搜索，不代用户签约。
- 复用现有 HTTP 客户端的固定端点、无重定向、无环境代理和无自动重试约束。密钥仅经约定环境引用注入，不入源码、公开证据或对话。
- 非流式、JSON Object，按本机 OMP compat 使用 `max_tokens:2048`，不发送 Qwen 的 enable_thinking、max_completion_tokens 或该路由未启用的 reasoning_effort。此参数不是完整计费输出上限证明；保留结构、完成状态、工具拒绝和引用校验。只采用 visible content，不保存隐藏推理或完整 provider 原始错误。

### Token 用量与失败边界（用户后续修订）

- 当前只记录 provider 返回的输入、输出、总量及可选缓存／推理 Token，不实现原 10 元／20 次闸门、发送前 tokenizer 证明、计价或通用预算平台。仅记录不限制花费，也不构成无限真实运行授权；实际运行清单仍单独批准。
- 计数采用可空的非负整数：显式 0 与缺失不同。完整、部分、未知和未调用分别记录；不估算、不补零、不用字符数代替 Token。缓存／推理与 completion 的关系不作未经验证的假定，保留 provider total，不自行累加或强制算式。
- 有效输出不因 usage 缺失／无效而失败；无效 usage 标 unknown。已获得可解析用量但输出被拒绝时，失败回执仍保留用量；超时、HTTP 错误或无法解析响应不等于未计费。
- 发送前仍持久化既有 requestId 预留，失败零发送；成功重放保留同一结果与用量、零新增发送；失败／未知请求不自动重试。保存后的回执是记录边界，不另建额度账本；删除／回滚回执、崩溃或写盘失败可能丢失用量及去重信息，不宣称账单完整性。
- 不保留密钥、隐藏推理、原始 provider 响应或客户问答到公开证据。细节与运行方式见 [开发说明](../development.md#s1-02-token-用量候选)。

## Testing Decisions

主验收面建议复用现有 `query` CLI：输入固定请求和配置，观察最终结果与保存回执，并对照真实服务的必要调用／用量证据。局部异常复用现有业务引擎与本地 HTTP 协议测试；不另建测试接口。该验收面随本文一起由用户审阅。

| AC | 输入／情形 | 可观察通过条件 |
|---|---|---|
| S1-A01 | 至少一个已审核真实全国等保问题 | 实际模型生成 `DRAFT_READY`；人工按冻结参考答案核对主体、条件、起算点、期限／材料及每条引用含义，全部满足才通过；不能用语句格式或模型自评代替 |
| S1-A02 | 快照中无可用依据 | `INSUFFICIENT_EVIDENCE`，无虚构义务；本地已确定无依据时真实模型调用增量为零 |
| S1-A03 | 相关来源时效未知、核验不足或未审核 | `NEEDS_REVIEW`，不发送模型请求、不冒充现行依据 |
| S1-A04 | 版本有效区间边界及重叠冲突 | 结束日不继续选旧版；区间内历史查询按记录选版本；冲突返回待复核，不挑选最方便的版本 |
| S1-A05 | 受控恶意正文 | 来源文字不能改端点、模型、权限或执行命令；不能诱发伪造引用、无来源义务或泄密；真实模型输出仍须人工核验，不能仅凭提示词或一次样例声称通用注入防护成立 |
| S1-A06 | 公开资料、范围与权限 | 原文／定位／版本／摘要可复核，许可和核验记录齐全；地方口径不泛化；其他四域不被标真实验收通过 |
| S1-A07 | 外发字段与模型输出 | 仅发送批准字段到固定百智云／Grok 路由；使用该路由参数，不臆称关闭思考或完整计费上界；不接受工具调用、伪造引用或无效输出，不记录秘密和隐藏推理 |
| S1-A08 | 完整／部分／缺失用量、错误与存储失败 | 记录 provider 计数，未知不记零，总量不重复加缓存／推理；拒绝输出仍保留已知用量；预留失败零发送，失败／未知不自动重试；不把用量记录称为预算控制 |
| S1-A09 | 相同请求重放与不同输入复用 ID | 完成结果原样重放且零新增模型调用；不同输入冲突；未完成请求不自动重试 |
| S1-A10 | 候选固定与证据交接 | 每项 AC 有预期／实际、真实命令、环境、退出结果、代码／配置／资料／输入摘要及人工复核结论；mock、live、FAIL、BLOCKED、NOT_RUN 分开 |

原始 SEED-S1 的正常、无依据、时效不明、版本边界、恶意正文五类链路均保留。安全／版本对抗数据必须明确标注为受控测试变体，与真实法规快照分离；不得把伪造效力、日期或恶意附文标成真实法规已审核内容。是否向真实模型发送受控变体须进入最终样例清单并经批准。

先例：现有五域与异常、无依据不调用模型、历史有效区间、来源摘要篡改、引用伪造、未完成不重试、网络与重定向、回执幂等测试，以及 CLI／loopback smoke。仅为新增真实不确定边界保留回归测试，不断言源码文本、转发细节或固定回答措辞。

### S1-02/r1 软件验收映射

以下是用户修订后的七项软件验收，替代 #2 发布时种子的模型／费用部分；原种子保留历史，实际发布版本及验收回执以 GitHub #2 为准。

1. 合法草稿、引用集合与人工复核标记正确；非法结构、引用、工具、截断及错误不保存为成功。
2. 固定百智云／Grok 请求及最小外发集合不能被问题或正文覆盖；无代理、重定向、自动重试或私有推理／凭据外泄。
3. 完整／部分／未知用量和显式零可区分；只保留 provider 计数，不强制总量算式或补估；缺失计数不阻断有效草稿。
4. 不要求原试验策略／价格／计数证明；仍证明预留存储失败零发送。已知用量下拒绝输出保留计数，错误／超时记未知；用量缺失不封锁后续新请求。
5. 成功重放结果与用量不变、零新增发送；相同 ID 不同输入冲突；失败／未知同 ID 为 `PREVIOUS_EXECUTION_UNRESOLVED`。
6. 网络默认不获准；不包含真实凭据；非批准模型端点拒绝；X1 原生模式仍只允许合成资料及原文提取。
7. 在 `.go-version` 目标工具链运行 `make verify` 与真实 CLI 的本地模拟，固定命令、环境和候选摘要；真实调用单列 NOT_RUN。

实施后使用仓库 `make verify`，目标 Go 读取 `.go-version`；真实模型验收另行运行，离线 PASS 不代替 live。Token／失败边界用受控本地服务验证，不为计数测试发送公网请求。
