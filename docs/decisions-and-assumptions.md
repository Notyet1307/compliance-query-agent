# 已确认、推荐和待验证

| 分类 | 内容 | 下一动作 |
|---|---|---|
| 已确认 | 五类安全合规查询，独立智能体，agent-compose / LLM / OctoBus / Accord 关系 | OMP 不随意改成新聊天平台或五 Agent 团队 |
| 推荐，未审批 | 产品名 Compliance Query Agent，角色名“合规资料研究员” | 用户可改名，不影响业务边界 |
| 推荐，未审批 | Go 固定查询流程；command 模式由 agent-compose 承载 | X1 验证所选发行版/guest ABI |
| 推荐，未审批 | 首条真实知识切片先做等保；随后覆盖剩余四域 | 选择具备使用权的实际输入/正确答案 |
| 推荐，未审批 | 不使用向量 DB、队列；先关键词基线/文件回执 | 真实评测显示不足后再引入额外组件 |
| 待验证 | 本机 OMP/Matt Skills/Go/agent-compose/Docker/OctoBus 版本与权限 | B0，禁止凭文档写 PASS |
| 待验证 | 原生 capset 注入的实际 URL、调用形状、超时/取消与结果通道 | X1，一次只读查询试验 |
| 待验证 | Accord 当前固定角色和合成 source manifest 如何合法扩展 | S3，在 Accord 侧形成批准 Spec |
| 未决 | 法规标准来源、使用权、更新责任、行业/地域覆盖 | S1，不能擅自抓取或打包标准全文 |
| 未决 | 模型、费用上限、远程传输策略、客户保密边界 | live 前批准，不自动默认公网模型 |
| 未决 | 新仓库名称、可见性、许可证、发布方式 | 用户选择；启动包未创建远端 |
| 未决 | 跨沙箱回执持久化/恢复语义 | X1/S2，与 Accord Invocation 权威对齐 |

初始代码仅供验证上述推荐，不代表用户已批准每一个技术决定。更改推荐须说明业务代价，关键决定记录为 ADR，不能静默改写验收预期。
