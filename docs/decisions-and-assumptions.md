## S2 收敛中的源码事实（尚非运行验收）

- 固定 agent-compose `043b763f05304c3a55f1bd3f4eb8504a591aa4ba` 已有 command 子进程可用的模型代理，上游模型密钥可留在 daemon；guest 的代理凭据绑定 sandbox/provider/协议，**不构成单模型白名单或费用上限**。[凭据范围源码](https://github.com/chaitin/agent-compose/blob/043b763f05304c3a55f1bd3f4eb8504a591aa4ba/pkg/llms/runtime_facade_target.go)。现有 X1 Codex 槽位的 Responses 凭据与 CQA Chat Completions 不匹配；用户已选平台代理方向，但兼容配置及真实模型转发尚未运行验证。
- 代理地址带 sandbox ID（[源码](https://github.com/chaitin/agent-compose/blob/043b763f05304c3a55f1bd3f4eb8504a591aa4ba/pkg/llms/runtimefacade/startup_config.go)），而 `internal/agent/engine.go` 将整个 Config 纳入回执摘要。若把解析后的临时代理地址当成稳定配置，新 sandbox 即使读到旧回执也会冲突；设计须区分稳定业务／模型／权限配置与临时运行地址，不能顺手取消真正的配置绑定。
- 既有 Store 支持已完成结果重放，固定平台版本支持可写 bind；稳定的专用宿主目录和 guest 路径具有源码可行性，但跨重建挂载尚未实测。`NewStore` 会创建缺失目录，缺失回执会被当成新请求，不能声称它能自动识别被删记录或存储丢失。重建及故障范围按上表确认；不引入数据库／队列，也不把持久挂载等同于升级迁移或删库恢复。
- OctoBus 固定方法 Search 本身不要求管理权限；平台目录注入使用管理 API。仅以 capset 查询凭据运行完整链路尚未验证，不能把“目录失败可能仅告警”当成成功证据，也不能自动沿用或升级为 X1 的管理级测试凭据。完整只读核对及交叉约束保存在私有 `.local/s2-design/`，不包含实施或运行授权。
