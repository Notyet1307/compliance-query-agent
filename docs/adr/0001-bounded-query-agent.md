# ADR-0001：固定查询流程，而非新的自治执行平台

状态：PROPOSED；日期：2026-09-10。

背景：用户需要可被 Accord 使用的领域智能体，而 Accord 已承担协作和治理。首个场景最重要的是范围、时效、依据和失败解释，不是任意操作工具。

建议决定：Go 单进程负责一次查询，LLM 只做受限归纳；外部工具限制为经批准的查询；agent-compose 提供 guest 生命周期，OctoBus 提供数据方法，Accord 保留权限/上下文/结果接受和发布。

代价：当前不具备开放式自主研究；关键词检索覆盖有限；须单独解决跨沙箱请求身份与结果回传。收益是输入输出可测、无需双重 LLM 循环、不引入新 Controller。

备选：Pi prompt + 自由工具循环。暂不选择，因为它增加 shell/tool 权限和推理不确定性；若真实评测证明需要多步研究，再以单独 Spec 验证。

本 ADR 不批准 agent-compose/OctoBus 的安装、许可使用、网络访问或真实 Accord 集成。
