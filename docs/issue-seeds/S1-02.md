## User outcome

操作者用现有 query CLI 运行有限样例时，程序只向固定服务发送批准字段，得到合格参考草稿或明确失败；额度不足、费用上界不可靠、预留失败或前次结果未知时，不额外发送请求。

## What to build

复用业务引擎、生成客户端及回执，补齐百炼北京阿里云直供 `qwen3.7-plus-2026-05-26` 所需的非思考、非流式 JSON 请求和完整输出限制。保持固定端点、无重定向／环境代理／自动重试，不扩展成多模型框架。

实现本次试验必要的有限调用保护：预算10元，最多20次真实已发请求；发送前检查并持久化保守占用，失败／未知仍占额度，重启、新 requestId 或业务回执清理不能刷新试验额度。费用按冻结价格、完整输入的可验证计数／保守上界与完整输出上界预留；无法证明不超限就不发请求。输入目标上限8,000 Token，输出限制2,048 Token，保守费用计入官方说明的误差；不能拿字符长度充当 Token 计数。

使用本地受控 HTTP 服务从 CLI 贯通生成、拒绝、保存回执与重启重放，不需要真实法律资料即可验证软件边界。测试数据明确为合成，不称为真实模型／资料集成通过；不得为了验证20次阈值真的发送20次公网请求。

## Acceptance criteria

- [ ] CLI 在受控服务返回合法草稿时得到 `DRAFT_READY`，引用来自输入集合，保持人工复核标记；非法结构、伪造引用、工具调用、截断及错误得到明确失败，不保存为成功。
- [ ] 对实际发往受控服务的请求验证仅有批准的数据，固定配置不能由问题或恶意正文覆盖；非思考与完整输出限制符合已核验接口，完整 provider 错误、密钥和隐藏推理不进入公开证据。
- [ ] 给出覆盖所有外发字段的完整输入计数／保守上界及费用证明；输出误差、失败／未知、价格变化均保守处理。前提不足零新增发送，不因免费额度或账单延迟继续执行。
- [ ] 最多20次已发请求、预算不足和发送前预留／存储失败的拒绝边界由受控服务观测证明；并发或重启不超发，不通过新 ID 获得新试验额度。
- [ ] 成功重放零新增发送；相同 ID 不同输入冲突；失败／未知请求保守占额度并遵循 `PREVIOUS_EXECUTION_UNRESOLVED`，无自动重试。
- [ ] 网络默认不获准；不存在可直接使用的真实密钥／未核实域名配置；X1 原生模式仍只接受合成资料及原文提取。
- [ ] 在 `.go-version` 所指目标工具链运行 `make verify` 及 CLI 受控服务场景；保存环境、命令、用量／计数观察和候选摘要，所有结果明确标本地模拟，真实调用 NOT_RUN。
