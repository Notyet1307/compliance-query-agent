## What to build

查询者在真实受管 guest 中，经已验证的仅查询 OctoBus 通路获取同一测试文档，通过 agent-compose 既有模型代理调用固定百智云 `grok-4.6`，得到带引用与 Token 记录的 `DRAFT_READY`。同一完成业务请求在重复提交、实际 guest 容器替换以及同机同项目／角色的新 sandbox 中都返回原结果，不再次 Search 或调用模型。

将模型接入、稳定业务身份与持久回执放在**同一候选构建**内实现和验证：复用 Engine／Store／生成客户端，不新增数据库、队列或代理服务。先分离临时 sandbox 代理地址与稳定配置绑定，完成专用持久挂载及故障阻断，再冻结构建进行真实正常调用和后续重放。不是先完成一次真实生成，再更改摘要／构建或复制旧回执来凑恢复通过。

CQA 固定 Grok、Chat Completions、S1 最小外发范围与输出／用量契约。guest 只持平台代理凭据，上游模型密钥留在 daemon；现有代理是 provider 范围而非单模型白名单或费用上限。使用明确的受管测试配置，默认禁网，不能直接解除旧 X1 的 LLM 限制或让正式资料模式接受 synthetic。受管端点和凭据只来自受信部署／平台，不能放开任意 HTTP、读取 OMP 凭据或回退直连。

恢复保证只限同机、同项目／角色、相同构建及稳定业务配置下的已完成回执。模型选择、capset／instance、业务输入与关联仍绑定；平台 run／sandbox 引用单独作为执行证据，动态地址和同权限凭据轮换不制造业务冲突。未知请求不自动恢复。
